주문내역을 내려줄 때 가격 멱등성에 대한 고민

메뉴 가격 변경 시 주문 내역의 가격 일관성 유지 방법

문제 상황 (Problem)#

메뉴 가격 변경 시 주문 내역의 불일치 문제가 발생했습니다.

예시#

  • 제육이 1,000원에서 2,000원으로 인상
  • 1,000원에 주문한 고객의 주문 내역이 현재 가격인 2,000원으로 표시

원인#

현재 시스템은 메뉴 내역 조회 시 현재 연결된 메뉴와 옵션을 참조하고 있어, 메뉴 정보 변경 후 과거 주문 내역을 조회하면 당시 가격이 아닌 변경된 가격이 반영되었습니다.

해결책 (Solution)#

방법 1: 히스토리 테이블 관리#

메뉴와 옵션의 히스토리 테이블을 별도로 생성하여, 주문 시점의 메뉴 정보를 저장하고 주문 내역 조회 시 이를 참조하는 방식입니다.

장점:

  • 모든 변경 이력 추적 가능
  • 데이터 무결성 보장

단점:

  • 주문마다 히스토리 레코드 생성
  • 테이블 구조 복잡화

방법 2: PUT 방식으로 메뉴 관리 (선택)#

기존의 부분 수정(PATCH) 방식이 아닌 전체 교체(PUT) 방식으로 메뉴를 관리하여 변경 전 정보를 유지하는 방식입니다.

장점:

  • 메뉴 변경 시에만 새 레코드 생성
  • 구현 단순화

단점:

  • 메뉴 전체 교체 필요

최종 선택#

방법 2 (PUT 방식) 선택

이유: 주문 빈도와 메뉴 변경 빈도를 고려할 때, 두 번째 방식이 생성되는 레코드 수가 적어 더 효율적이었습니다.

핵심: 주문 시점의 가격을 보존하려면 메뉴 변경 전략을 신중히 선택해야 합니다.
